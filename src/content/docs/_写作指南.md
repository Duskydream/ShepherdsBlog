# 写作指南

这个 vault 就是 `F:\Starlight\src\content\docs`，也就是 Astro 站点的内容目录。
这里写的每一个 `.md` 都会变成线上页面，所以有几条硬规则。

## 草稿：用 `draft: true`

在 frontmatter 里写 `draft: true`：

```yaml
---
title: 写了一半的文章
date: 2026-10-11
draft: true
---
```

- **线上构建会跳过它**（`pnpm build` 不生成页面）
- **本地 `pnpm dev` 仍能预览**，所以可以边写边看效果
- 写完把 `draft: true` 改成 `false`（或删掉这一行，默认就是 false）就发布了

> ⚠️ 别指望靠目录名藏草稿。Astro 的 glob 是 `**/[^_]*.{md,mdx}`，
> 下划线规则只看**文件名**，不看目录：`_drafts/foo.md` 照样会被发布，
> 只有 `_drafts/_foo.md`（文件名带 `_`）才会被彻底跳过 —— 但那样连 dev 里也看不到。
> 所以草稿统一用 `draft: true`。

## frontmatter 必填项

| 字段 | 要求 |
|---|---|
| `title` | **必填**。缺了构建直接报错 |
| `date` | 写 `2026-03-03`，**不要加引号**（sitemap 用正则抓这一行） |
| `description` | 选填，用于列表页摘要和 SEO |
| `author` | 选填 |
| `tags` / `categories` | 选填，数组格式 `["Music", "Yorushika"]` |
| `draft` | 选填，`true` = 草稿不发布 |

## 文件名

**不要有空格。** `astro.config.mjs` 会把文件名转小写并把空白折叠成 `-`，
`2025-10-18-Revue Starlight.md` 就踩过这个坑，URL 会变成
`/log/2025-10-18-revue-starlight/`。

用连字符：`2026-10-11-My-New-Post.md` 或直接中文：`关于遗忘.md`。

## 图片

两种写法都行，各有取舍：

**图床（推荐给大图）** —— 正文图片目前走图床（`https://pic1.imgdb.cn/...`）：

```markdown
![描述](https://pic1.imgdb.cn/item/xxxx.png "可选的 title")
```

`scripts/build-images.mjs` 会把它下载、压成 480/832/1280/1600 四档 WebP，
并生成 `srcset`，手机上不会去下 1.7 MB 的原图。

**本地附件** —— 直接把图拖进笔记，Obsidian 会存到 `assets/` 并插入相对路径：

```markdown
![描述](../assets/xxx.png)
```

- 路径是**相对当前笔记**的：`blog/` 里的笔记必须写 `../assets/xxx.png`，
  写成 `assets/xxx.png` 会构建失败（`[ImageNotFound]`）
- 文件不存在会**直接让构建挂掉**，删图前先确认没别的地方引用
- Astro 会压成 WebP，但**只出一档尺寸**（没有 srcset），所以大图还是走图床更省流量
- 别把图片放到 `assets/` 以外的地方乱塞，那个目录是给附件用的

> 两个设置已经在 `.obsidian/app.json` 里配好了，不用再动：
> `useMarkdownLinks: true`（否则拖图会插成 `![[附件.png]]`，
> `build-images.mjs` 不认这个语法）、`attachmentFolderPath: "assets"`。

## 站内链接

**直接用 Obsidian 的方式写就行**，`astro.config.mjs` 里的
`remarkRewriteObsidianLinks` 会把它们改写成路由：

```markdown
[同目录的文章](second-person.md)
[跨目录的文章](../coding-notes/位运算.md)
[带锚点](../coding-notes/BFS初探.md#举例)
```

分别会变成 `/blog/second-person/`、`/coding-notes/位运算/`、
`/coding-notes/bfs初探/#举例`。文件名里的空格和大小写会被归一化，
和 `collectContentDates()` 的规则一致。

**锚点直接写标题原文就行**，插件会把它转成页面里真实的 id：

```markdown
[跳过去](../coding-notes/BFS初探.md#DFS -> 利用栈的天然回溯性质，走到死路自动回头)
```

上例会变成 `#dfs---利用栈的天然回溯性质走到死路自动回头`
（标点被去掉、空格变连字符、转小写）。同一个页面内也可以写 `[跳到本节](#举例)`。

> 标题里带空格时，markdown 链接的 URL 不能有裸空格 —— 要么用尖括号包起来
> `[x](<../log/2025-10-18-Revue Starlight.md>)`，要么让 Obsidian 自己写
> （它知道该怎么转义）。平时用 Obsidian 的自动补全就不会踩到。

> 如果**目标文件不存在**，链接会原样留在页面里（点进去 404）。
> 这是故意的：让 Obsidian 的「未解析链接」提示来提醒你，构建不会瞎猜。
>
> 外链、`/绝对路径` 都不受影响，原样放过。

## 目录

| 目录 | 用途 |
|---|---|
| `blog/` | 长文、翻译、书评 |
| `coding-notes/` | 算法与编程笔记 |
| `log/` | 日志、短记 |
| `assets/` | 图片附件（Obsidian 拖图自动存这里） |
| `_templates/` | 模板（`_` 前缀，不会被发布） |

## 模板

`Ctrl+P` → 搜 "模板" → 插入模板：

- `_post.md` —— 完整 frontmatter（blog / coding-notes 用）
- `_log.md` —— 精简 frontmatter（log 用）

## 提交

用 Obsidian Git 插件手动 commit / push。自动提交已关闭，因为
`scripts/deploy.mjs` 有个守卫：**有未跟踪文件就拒绝部署**。
新建的文件要先 `git add` 再 commit。
